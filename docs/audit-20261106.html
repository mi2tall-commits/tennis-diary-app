2026-11-06 · 브랜치 audit/20261106 · 커밋 8개(아직 GitHub에 올리지 않음, 배포 안 함)

결론. 확인된 문제 10개 중 9개를 코드로 고쳤고, 자동 시험 24개가 모두 통과합니다(고치기 전에는 16개 실패). 가장 큰 위험 두 가지는 코드만으로 끝나지 않습니다. 공개 저장소에 노출된 Gemini 키는 직접 폐기해야 하고, 로그인 없이 누구나 일지를 지우고 고칠 수 있는 문제(#2)는 아직 그대로입니다. 고친 코드도 아직 실제 앱에 올라가지 않았습니다. 아래 순서대로 정해 주세요.
주인이 정할 것 (위에서부터 급한 순)
  1. Gemini 키 즉시 폐기·재발급. Google AI Studio에서 지금 키를 지우고 새 키를 만든 뒤, Apps Script 편집기 > 프로젝트 설정 > 스크립트 속성에 GEMINI_API_KEY로 넣으세요. 코드에서 대체 키를 뺐기 때문에, 속성이 비어 있는 채로 배포하면 AI 분석 기능이 멈춥니다. git 기록에 남은 옛 키를 지울지(기록 다시 쓰기)도 정해야 합니다. 폐기만 하면 옛 키는 쓸모가 없어지므로 기록 정리는 급하지 않습니다.
  2. 누가 쓸 수 있게 할지(#2). 세 가지 안이 있습니다. ① 쓰기·AI 요청에 비밀 PIN을 같이 보내게 하기(지금 화면 유지, 반나절 작업) ② 구글 로그인한 사람만(ANYONE) ③ 나만(MYSELF). 추천은 ①입니다. 가족·지인이 지금처럼 쓰면서도 모르는 사람은 막을 수 있습니다. 사진 폴더의 "링크가 있는 누구나 보기" 공유를 유지할지도 함께 정해 주세요.
  3. 고친 코드 배포. clasp push 후 새 버전 배포, GitHub Pages에도 index.html 반영. 이번 점검에서는 배포하지 않았습니다.
  4. 일지마다 고유 ID 열 추가(#4 근본 해결). 시트에 열을 하나 더 만들고 기존 행에 ID를 채우는 작업입니다. 이번에는 날짜·제목으로 대조하는 안전장치만 넣었습니다.
  5. 영상 크기 한도. 지금은 한 편 35MB, 최대 5편까지 받습니다. Apps Script 요청 한도에 걸리기 쉬우므로 10MB·1편 정도로 줄일지 정해 주세요. 이번에는 실패하면 알려 주는 것까지만 고쳤습니다.
